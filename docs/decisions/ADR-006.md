# ADR-006 — Registration, Session Settings and SMS OTP

Date: 2026-10-24
Status: USER-APPROVED SCOPE; DEFAULT SMS NUMBERS PROVISIONAL

Supersedes ADR-003's uniform 1440-minute token expiration and ADR-005's provisional registration assumptions.

- Members may **self-register**, prioritizing email verification. Mobile OTP registration/verification must also be implemented; do not require paid SMS for test mode.
- Members sign in with email OR mobile number and password. Each App maintains its own accounts, database and auth tokens.
- Member app login should persist by default without a fixed expiry; administrators must be able to configure member session/token expiration from each App's Filament settings.
- Filament admin session defaults to **7 days of inactivity**, sliding with activity, and the admin may change this duration.
- Each App has exactly **one admin operator (the owner)**, with separate app-local credentials and data. No shared admin database or SSO. Member permissions must never grant Filament access.
- Each App's Filament settings has tabs for member/admin session limits, registration/verification and SMS OTP settings.
- SMS must support adapters for three Taiwanese providers (Mitake, EVERY8D, SMSGO) and a fake test provider; provider credentials are server-side only.
- Admin configures global hourly SMS limit and per-phone resend cooldown; add per-phone hourly limit, OTP lifetime and attempt cap.
- Suggested defaults **not approved as final values**: global 100/hour, phone 3/hour, resend 3 minutes, OTP 5 minutes, 5 attempts. Do not treat these as final deployment policy.
- No production deployment or real SMS sending without credentials and explicit approval.

Implementation notes: Do not use Sanctum's fixed expiry for member tokens if persistent login is selected. A per-app policy and server-side last-activity check are needed for configurable idle expiry. Laravel web sessions require separate handling for sliding admin idle expiry; cookie/session settings alone are insufficient evidence of compliance.

Outstanding security design: verified email/mobile uniqueness, password recovery, E.164 normalization, OTP abuse controls, SMS provider API request/response details and migration approval. No unreviewed production schema.
