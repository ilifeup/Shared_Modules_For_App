# ADR-004 — Independent App Identity and Database Isolation

Date: 2026-10-24
Status: APPROVED

## Decision
Tiandi, Wuxiang and EachCore are **three independent applications**.

- Each App owns a **separate database**, member accounts and authentication identity.
- No cross-App account lookup, shared users table, common login, SSO or central token service.
- Sanctum tokens are issued, validated, expired and revoked by the issuing App only.
- The same email may represent unrelated accounts in different Apps. A token from App A must never authorize App B.
- The shared modules repository is a **source-code/package repository**, not a fourth deployed backend or identity provider.
- Filament, migrations, policies, admin provisioning and application-specific roles belong to each App; shared packages may provide opt-in reusable helpers without assuming global roles or global user IDs.
- API contracts may be reusable, but each App's API base URL and database credentials are distinct.

## Scope boundary
This ADR settles architecture isolation only. It **does not approve** concrete users/notices migration columns, role/permission table design, Filament access policy, login identifier or member account creation rules. These remain pending user review.

## S1 acceptance criteria
1. A synthetic Tiandi account cannot log in to Wuxiang/EachCore merely by having the same email or ID.
2. Tiandi Sanctum bearer token is rejected by Wuxiang and EachCore (401).
3. Logging out of Tiandi revokes only its current Tiandi token.
4. Schema migrations run against one App's disposable test DB without altering another.
5. Shared modules contain no hard-coded cross-App database connection or centralized auth endpoint.
