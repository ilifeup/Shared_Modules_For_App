# ADR-005 — S1 Member Fields, Notices, Local Roles and Dual Login

Date: 2026-10-24
Status: APPROVED IN PRINCIPLE; PHONE AUTH DETAILS PENDING

## User-approved decisions

- Tiandi, Wuxiang and EachCore each have their own database, accounts and authentication (ADR-004).
- A member signs in with **either email or mobile number**, plus password. This is one login input, not two separate account systems.
- Keep Laravel `users.name` and add user-editable `display_name`. S1 member profile PATCH may update **only display_name**.
- Minimal notice business columns: `title`, `body`, `status`, `published_at` (plus necessary primary key/timestamps).
- Each App owns its own member/admin role assignment and policies; **only admins enter Filament**.
- Sanctum lifetime is 1440 minutes; logout revokes the current token (ADR-003).
- Synthetic test data and disposable CI only; no production deployment.

## Decisions not yet made

- Whether a mobile number must be verified by SMS/OTP before login; whether email verification is required.
- Accepted country codes and normalization format (suggest E.164), uniqueness rules for mobile/email, and behavior for duplicate identifiers.
- Whether login should allow unverified identifiers, and how users recover passwords or change mobile numbers.
- Specific migrations and policies must implement the approved boundaries without silently deciding the unresolved verification/security rules.

## Implementation contract

The Flutter client submits `identifier` and `password`; the App's Laravel endpoint resolves the identifier against **its own database only**. No central auth service, no shared login, no shared DB. Until the backend request contract and verification rules are finalized, this is a proposed API field name; backend integration tests must confirm it.
