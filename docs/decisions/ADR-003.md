# ADR-003 — S1-A Token Policy and Deferred Schema/Role Review

Date: 2026-10-23
Status: PARTIALLY APPROVED

## Approved
- Sanctum token expiration: **1440 minutes (24 hours)**.
- Logout revokes **the current token**.
- All work and CI use synthetic/disposable test data. No production deployment.

## Explicitly not approved
- Persistent users/notices schema and migrations: **DISCUSS FIRST**.
- Authorization model, role names, Filament panel access and permissions: **DISCUSS FIRST**.

## Implementation boundary
A stateless token policy constant, request/response contract tests, disposable harness preflight and documentation may proceed. Do not create or merge authoritative database migrations, role seeds, production auth configuration or Filament authorization code until the user approves specific designs.

## Design questions for review
1. Should the S1 users table retain Laravel's default `name` and add `display_name`, or use `name` as the only display field? Is email a required login identifier for synthetic accounts?
2. Should notices use a minimal `draft/published` status and optional UTC `published_at`? Should unpublished notices be hidden from all member APIs?
3. Are `member` and `admin` sufficient S1 roles, and should only admins enter Filament? Should the admin role be reusable across apps or app-local?

These questions are pending, not implied approvals.
